# FREM-S12 complete successor plan

Historical status at creation: `DRAFT_NOT_FROZEN`. Planning date: 18 October
2026. The operative pre-data design is now the frozen P0v7 protocol in
`successors/frem_s12/src/frem_s12/protocol_p0_v7.json`; this document remains
the preserved original plan and is not itself an execution receipt.

## 1. Evidence boundary

S12 is a separate proposed successor. It does not revise S8's inconclusive
predictive/economic failure, does not consume S9/S10, and does not replace or
unblock S11. S11 remains a fixed mandatory control if S12 reaches execution.

No S12 market data, fit, score, ledger, Kaggle session or protected outcome
exists. This document is a work plan, not experimental evidence or permission
to run every preset.

## 2. Problem and proposed contribution

Fixed or heuristic mixtures of forecast experts can confuse persistent skill
with transient correlated errors under regime change. The S12 candidate is a
causally delayed, stability-constrained neural router over multiscale
Fourier-reservoir and engram-retrieval scenario laws. It receives only causal
state summaries and matured historical proper-score regret. It emits a finite
joint scenario law whose composition is completely retained.

The falsifiable contribution is narrow: under matched information, search and
compute, the learned router should improve joint probabilistic forecasting over
both the frozen S11 stacker and the strongest predeclared non-FREM baseline
across repeated chronological shifts. Novelty is a candidate, not established.

## 3. Workstream A — literature and idea gate

Build a dated primary-source review covering:

- probabilistic forecast combination and online aggregation;
- delayed-feedback and nonstationary expert advice;
- reservoir computing and random Fourier state models;
- episodic/nearest-context retrieval and mixture-of-experts routing;
- multivariate energy and variogram scoring;
- distributional financial forecasting and honest negative findings.

Produce a closest-method table with mechanism, information, objective,
adaptation, compute, datasets and claims. State exactly which combination, if
any, is new. If the router is reducible to a standard method without a meaningful
scientific distinction, simplify or stop before implementation.

**Checkpoint A:** `IDEA_READY` only after every blocker in `FLAW_CHECKLIST.md`
has a defensible disposition.

## 4. Workstream B — source and contamination gate

Audit candidate official portfolio families without inspecting proposed
protected numeric outcomes. Record URLs, release structure, timestamps, file
formats, licensing/redistribution limits, calendar coverage and construction
method. Build a contamination ledger of every date/series/metric previously
accessed anywhere in S1-S11.

Use at least six and target eight repeated walk-forward development folds, each
with at least 120 months training, 24 months inner validation and 24 months test,
striding by 24 months. Purge the full label/feedback maturity interval. Exact
dates are frozen only after metadata-only coverage review.

Do not name a confirmation source until the exposure audit finds genuinely
unused outcomes. Public availability alone does not make data confirmatory.

**Checkpoint B:** exact sources, rights, calendars, folds and protected boundary
ready for a versioned P0 freeze.

## 5. Workstream C — model specification

Specify every equation before coding:

1. Train-only robust transformation and missingness mask.
2. Fixed random Fourier feature map.
3. Spectrally normalized recurrent reservoir state.
4. Matured engram write rule with bounded capacity and deterministic eviction.
5. Short, medium, long, nearest-context and tail-regime scenario retrieval.
6. Scenario normalization and support identity.
7. Router inputs from causal state, uncertainty and matured expert regret.
8. Router network, initialization, optimizer, regularization and stopping.
9. Simplex projection, cap and entropy/shrinkage stability constraint.
10. Delayed-feedback queue and evaluation-time update rule.
11. Finite-law output and exact energy/variogram score reconstruction.
12. Secondary policy mapping, costs and post-return state transition.

Record dimensions, units, complexity, numerical tolerances and failure behavior.
No material architecture choice may remain implicit.

**Checkpoint C:** `MODEL_SPECIFICATION_READY` and protocol version S12-P0.

## 6. Workstream D — methodology freeze

Mandatory controls are S11's fixed stacker, equal mixture, recency law,
shrinkage Gaussian, shrinkage Student-t, regularized VAR scenario model, one
credible compute-matched neural sequence model, and router-disabled candidate.

Primary support requires all of:

- at least 5% relative mean energy-score improvement against S11 and the best
  predeclared non-FREM control;
- Holm-corrected paired 95% hierarchical moving-block intervals above zero;
- at least 75% of eligible folds positive;
- no dataset family with a materially negative pooled effect;
- no more than 1% relative degradation on the variogram dependence guard;
- complete planned seeds/cells or an explicit invalid/incomplete disposition.

Secondary metrics cannot rescue the primary. Policy results are crossed across
forecast laws to separate prediction from decision rules.

The nested development search has at most 24 trials on seeds 11/29. To prevent
later-fold validation outcomes from leaking into earlier tests, selection uses
only Fold A validation (1998-1999), aggregated equally across the three
families and two search seeds: 144 search cells. It selects one candidate before
the fixed matrix. The fixed matrix uses seeds 11/29/47/71/97. Every failure,
OOM, timeout and nonfinite result is retained.

**Checkpoint D:** `METHODOLOGY_READY` with executable cell registry, statistical
reference implementation and frozen decision logic.

## 7. Workstream E — implementation

Implement a typed package with:

- immutable configuration and protocol readers;
- source/data/environment/split identity;
- CPU reference kernels and optional PyTorch GPU kernels;
- model, controls, training, inference and evaluation;
- atomic checkpoint/resume including all RNG and delayed-feedback state;
- one-use campaign/shard/cell consumption;
- complete raw forecasts, scenarios, weights, losses and profiling;
- no-overwrite artifact bundles and manifests;
- reconstruction-only audit, tables and figures;
- unit, mathematical, causal, gradient, shape, corruption, future-perturbation,
  cross-device and failure-preservation tests.

Optimization is allowed only after semantic equivalence tests. A behavior change
becomes a recorded successor amendment before any affected outcome is viewed.

**Checkpoint E:** `MODEL_AND_EXPERIMENT_SYSTEM_IMPLEMENTED`.

## 8. Workstream F — dry runs and Kaggle qualification

First run generated data locally. Then execute the staged private Kaggle plan in
`KAGGLE_CAMPAIGN.md`. S12 uses a new Kaggle-native public-data threat model; it
does not weaken or relabel S10's failed isolation requirement.

GPU use is conditional, not assumed. It must match CPU reference numerics within
frozen tolerances and provide at least 1.5x representative end-to-end speedup.
Otherwise heavy execution remains CPU-based.

The costed dry run must project the entire fixed registry within live quota and
the 60 GPU-hour, 120 CPU-hour, 2,000-cell and two-week development ceilings.

**Checkpoint F:** `RUN_READY` only with downloaded, hash-matched Kaggle receipts.

## 9. Workstream G — development execution

1. Consume nested search once.
2. Preserve the complete trial ledger and select one candidate.
3. Publish the selection identity before the fixed matrix.
4. Run sharded fixed core controls.
5. Run frozen ablations, robustness and scaling only after core completeness.
6. Download and hash-verify every saved output.
7. Reconstruct all metrics independently from raw arrays.
8. Apply the frozen rule exactly once.

No partial leaderboard, favorable fold, seed replacement, automatic retry or
threshold change can authorize extra scientific work.

## 10. Workstream H — disposition and confirmation

- **Negative/inconclusive:** close the frozen S12 version.
- **Invalid:** preserve it and create a prospectively corrected new freeze only
  for a genuine validity defect.
- **Positive development:** report bounded development support and freeze a
  genuinely unused confirmation study. Do not claim confirmed performance.

Confirmation requires its own data/provenance/contamination audit, protocol,
budget, exact source/environment identity and independent reproduction. It is
not included in the current heavy-development authorization.
