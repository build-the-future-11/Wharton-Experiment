# FREM-S12 P0 implementation

FREM-S12 is a proposed successor study, not a repair, rerun, or favorable
reinterpretation of S8-S11. S11 remains unconsumed and resource blocked under
its own P1 freeze. S12 asks a different question: whether a trainable causal
router over multiscale Fourier-reservoir and engram-retrieval specialists can
improve joint distribution forecasts under repeated walk-forward evaluation.

The P0v2 base protocol and P0v3 integrity amendment are preserved in
`protocol_p0.json` and `protocol_p0_v3.json`. The prospective Kaggle runtime
portability amendment is frozen in `protocol_p0_v4.json`, P0v5 delivery
hardening is preserved in `protocol_p0_v5.json`, P0v6 evidence reconstruction
is preserved in `protocol_p0_v6.json`, and the operative P0v7 end-to-end
evidence-chain amendment is frozen in `protocol_p0_v7.json`. The package
admits only the exact Python-major/minor and NumPy pairs declared there and
implements causal finite-law forecasting, the learned delayed router,
matched controls, policy diagnostics, immutable evidence bundles, exact-origin
checkpoints, complete-campaign analysis, and a thin Kaggle launcher. No market
bytes or protected outcomes were acquired or parsed in the implementation
session.

Core commands are `plan`, `qualify`, `qualify-kaggle`, `acquire`, `admit-data`,
`run-search-cell`, `select-search`, `run-cell`, `generated-smoke`, `shard-plan`,
`analyze`, and `verify-run-bundle`. Search is restricted to Fold A validation and produces one
source-current selection receipt. `run-cell` requires that receipt, the explicit
`--execute` flag, source-current environment/data receipts and a deterministic
consumption root. Search and fixed claims are one-use; only an exact checkpoint
resume with identical gates may reuse a claim. Every result path is no-overwrite
and hash-bound.

P0v3 retains every issued finite forecast law and outcome for independent score
reconstruction, separates policy targets from post-return holdings, averages
algorithmic seeds before hierarchical inference with synchronized shared-calendar
resampling across families, and prevents local engineering
receipts from admitting scientific work. Only `qualify-kaggle` can produce the
required scientific-scope environment receipt; the notebook fails closed when
that receipt is not admitted.

P0v4 changes no model, split, threshold, inference rule, search registry, fixed
matrix, or compute ceiling. It adds the Kaggle-observed Python 3.13 / NumPy 2.1.3
runtime pair, retains Python 3.12 / NumPy 2.5.4, verifies the wheel by exact
filename and SHA-256 under Kaggle's recursive read-only input layout, and keeps
all science gated behind a fresh exact-source qualification receipt.

P0v5 changes only delivery and resource admission. It installs the exact wheel
into a fresh isolated target, inventories every regular non-symlink input,
emits a no-overwrite hash/size run manifest, fixes the reference thread count,
and bases projections on the slowest of three byte-stable qualification
repeats. Model, cells, controls, thresholds, inference and budgets are unchanged.

P0v6 changes only evidence intake and target strictness. Search selection now
reloads raw finite laws and independently reconstructs every score. Fixed-matrix
analysis reconstructs energy scores, variogram scores, holdings and wealth from
raw arrays before trusting summaries. Downloaded Kaggle bundles have an exact
regular-file inventory verifier, target subprocesses treat Python warnings as
errors, and misplaced or symlink/special-file bundles fail closed. The model,
cells, controls, thresholds, inference and budgets remain unchanged.

P0v7 closes the remaining evidence-chain gaps without changing the scientific
design. Validation outcomes and finite laws are retained so the selected
non-FREM control can be reconstructed; search and fixed calendars must exactly
match the frozen registry; seed runs must share identical outcomes; complete
campaigns reject every foreign file; and every cell binds acquisition, data,
environment, source, selection and consumption evidence. Qualification intake
now validates the isolated installation identity, runtime allowlist, three
timing repeats, byte stability and recomputed resource projections before it
can report `eligible_for_next_stage`.

The next legitimate work is a Kaggle qualification run, followed by exact
source acquisition and admission. Market execution remains gated until those
receipts exist. Generated verification is engineering evidence only and cannot
support the P0 scientific claim.
